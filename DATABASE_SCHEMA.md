# Database Schema Documentation

## Overview
The `robot_memory.db` SQLite database serves as the persistent cognitive memory layer for the Rock64 robot system. It stores spatial memory, mission tasks, AI conversation history, telemetry data, and safety events.

**Location**: `C:\Desktop\Rock64 Robot\robot_memory.db`

**Total Tables**: 10

---

## Agent Guidelines

### ⚠️ CRITICAL RULES FOR AUTOMATED AGENTS

1. **READ-ONLY/APPEND-ONLY ACCESS**: Future agent loops must treat the database schema as immutable. Only `INSERT` and `SELECT` operations are permitted.

2. **FORBIDDEN OPERATIONS**: 
   - **NEVER** execute `DROP TABLE` commands
   - **NEVER** execute `ALTER TABLE` commands
   - **NEVER** modify existing table structures
   - **NEVER** delete or truncate tables

3. **DATA INTEGRITY**: All foreign key relationships must be preserved. The database uses `PRAGMA foreign_keys = ON` for referential integrity.

4. **SAFE OPERATIONS**:
   - `INSERT` - Add new records to existing tables
   - `SELECT` - Query data for decision-making
   - `UPDATE` - Only on non-structural columns (e.g., status fields with explicit business logic)

## Schema Documentation

### 1. Core System & Navigation Layer

#### `map_waypoints`
Stores physical coordinates of key static locations within the map grid.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Unique identifier |
| location_name | TEXT NOT NULL UNIQUE | e.g., 'charging_station', 'fume_hood', 'bench_1' |
| x_pos | REAL NOT NULL | X coordinate in map grid |
| y_pos | REAL NOT NULL | Y coordinate in map grid |
| z_pos | REAL DEFAULT 0.0 | Z coordinate (height) |
| theta_orientation | REAL DEFAULT 0.0 | Heading angle in radians |
| description | TEXT | Optional description |
| created_at | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Creation timestamp |

**Purpose**: Provides fixed reference points for navigation and spatial localization.

---

#### `spatial_memory`
Real-time tracking of physical objects discovered via vision/sensors.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Unique identifier |
| object_name | TEXT NOT NULL | e.g., 'beaker_500ml', 'red_marker' |
| x_pos | REAL NOT NULL | X coordinate of object |
| y_pos | REAL NOT NULL | Y coordinate of object |
| z_pos | REAL DEFAULT 0.0 | Z coordinate (height) |
| confidence | REAL NOT NULL | Object detection model accuracy (0.0 - 1.0) |
| associated_waypoint_id | INTEGER | Foreign key to map_waypoints |
| last_seen | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Last detection timestamp |

**Foreign Key**: `associated_waypoint_id` → `map_waypoints(id)` ON DELETE SET NULL

**Purpose**: Tracks dynamic objects in the environment with confidence scores and spatial relationships.

---

#### `robot_telemetry`
High-frequency hardware health data (periodically purged/aggregated).

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Unique identifier |
| battery_voltage | REAL | Battery voltage in volts |
| battery_percentage | REAL | Battery level percentage |
| motor_current_left | REAL | Left motor current draw |
| motor_current_right | REAL | Right motor current draw |
| wifi_signal_strength | INTEGER | WiFi signal strength in dBm |
| cpu_utilization | REAL | Rock64 CPU utilization percentage |
| cpu_temperature | REAL | Rock64 CPU temperature in Celsius |
| timestamp | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Measurement timestamp |

**Purpose**: Monitors hardware health for predictive maintenance and diagnostics.

### 2. Cognitive Layer & AI Task Management

#### `agent_cognitive_history`
Persistent chat/instruction log for the local LM Studio instance.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Unique identifier |
| session_id | TEXT NOT NULL | Groups multi-turn prompt iterations |
| speaker | TEXT NOT NULL | 'system', 'user', 'robot_agent' |
| message_content | TEXT NOT NULL | Full prompt or response text |
| tokens_used | INTEGER | Token count for the message |
| model_identifier | TEXT | Specific model version (e.g., 'llama3:8b') |
| timestamp | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Message timestamp |

**Purpose**: Enables conversation context tracking, debugging, and learning from AI interactions.

---

#### `mission_control`
High-level operational tasks generated by AI or manually assigned.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Unique identifier |
| task_name | TEXT NOT NULL | e.g., 'locate_missing_reagent' |
| priority_level | INTEGER DEFAULT 3 | 1 (Critical) to 5 (Low/Idle) |
| task_status | TEXT DEFAULT 'pending' | 'pending', 'in_progress', 'completed', 'failed' |
| failure_reason | TEXT | Explanation if task failed |
| assigned_at | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Task creation timestamp |
| updated_at | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Last update timestamp |

**Trigger**: `update_mission_timestamp` automatically updates `updated_at` on status changes.

**Purpose**: Manages the queue of high-level objectives for the robot.

---

#### `execution_steps`
Detailed step-by-step physical breakdown of active high-level tasks.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Unique identifier |
| mission_id | INTEGER NOT NULL | Foreign key to mission_control |
| step_sequence | INTEGER NOT NULL | Execution order (1, 2, 3...) |
| action_type | TEXT NOT NULL | 'navigate', 'scan', 'wait', 'actuate' |
| target_parameters | TEXT | JSON string of parameters (e.g., '{"x": 1.2, "y": -0.4}') |
| step_status | TEXT DEFAULT 'pending' | 'pending', 'in_progress', 'completed', 'failed' |

**Foreign Key**: `mission_id` → `mission_control(id)` ON DELETE CASCADE

**Purpose**: Decomposes missions into executable physical actions with parameterized targets.

## Database Triggers

### `update_mission_timestamp`
Automatically updates the `updated_at` column in `mission_control` whenever a row is updated.

```sql
CREATE TRIGGER IF NOT EXISTS update_mission_timestamp
AFTER UPDATE ON mission_control
BEGIN
    UPDATE mission_control
    SET updated_at = CURRENT_TIMESTAMP
    WHERE id = NEW.id;
END;
```

**Purpose**: Ensures accurate task timing without requiring manual timestamp updates.

## Foreign Key Constraints

The database enforces referential integrity with the following relationships:

1. `spatial_memory.associated_waypoint_id` → `map_waypoints(id)` (SET NULL on delete)
2. `execution_steps.mission_id` → `mission_control(id)` (CASCADE on delete)
3. `equipment_registry.current_location_id` → `map_waypoints(id)` (SET NULL on delete)

**Foreign Keys Enabled**: `PRAGMA foreign_keys = ON`
